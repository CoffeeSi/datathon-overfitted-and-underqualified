# Action checkpoint и реальная проверка backend — 18 октября 2026

Обучен настоящий R3D-18 multilabel checkpoint для интеграционной проверки двух
типов: `client_identity_check_not_visible` и `unsecured_accepted_cash`.
Это проверка исполнения сервиса, а не подтверждение качества распознавания.

## Качество на размеченных validation-окнах

При фиксированном пороге 0.7:

- Идентификация клиента: TP=0, FN=1, FP=0, TN=6; precision/recall/F1 = 0.
- Необеспеченные наличные: TP=0, FN=1, FP=1, TN=2; precision/recall/F1 = 0.
- Macro F1 = 0. Неизвестные метки исключены из подсчёта.

В каждом типе есть только одно положительное validation-видео. Высокие train-метрики
не переносятся на validation. `validated_types` в существующем формате checkpoint
означает наличие положительных и отрицательных примеров, а не успешную приёмку качества.
Порог и эпоха после просмотра validation не подбирались. Quality approval не выдан.

## Запуск для команды backend

Использовать новый конфиг явно; прежний `action_service.yaml` не переключался:

```powershell
$env:PYTHONPATH = "src"
$env:FORTEBANK_ANALYZER_FACTORY = "overfitted_underqualified.backend.local_analyzer:create_analyzer"
$env:FORTEBANK_ACTION_CONFIG = "configs/action_service_backend_smoke.yaml"
$env:FORTEBANK_ENABLE_MOCK_RESULTS = "false"
$SecureKey = Read-Host "API key" -AsSecureString
$env:FORTEBANK_API_KEY = [System.Net.NetworkCredential]::new("", $SecureKey).Password
.\.venv\Scripts\python.exe -m uvicorn overfitted_underqualified.backend.api:app --env-file .env --host 127.0.0.1 --port 8000
```

Освободить порт штатной остановкой своего прежнего сервера перед запуском.
Конфиг использует CUDA; для машины без NVIDIA нужно явно выбрать CPU и отдельно
проверить время обработки. Обе папки весов из конфига необходимы на машине сервиса.
