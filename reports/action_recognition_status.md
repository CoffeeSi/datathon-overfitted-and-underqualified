## Реализовано

- Отдельная frozen R3D-18 sigmoid-голова, masked BCE, 16 кадров, прежнее декодирование
  и pretrained preprocessing; фиксированные seed/пороги, неизменяемые backbone/BatchNorm.
- Сохранение action checkpoint, class mapping, схемы, конфигурации, происхождения
  pretrained-весов, хешей, истории и предсказаний. Восстановление без скачивания весов.
- Конкретный `R3DActionRecognizer`, поддержка нескольких типов и отказа. Обработка
  на уровне окон до объединения; разные типы и разрывы не теряются.
- `link_action` добавляет существующие ссылки, условия применимости и ограничения;
  юридическое заключение не формируется. Бинарный score и type confidence разделены.
- Реальный async backend adapter с однократной загрузкой, работой вне event loop и
  ожиданием фактического завершения потока при отмене. Без пригодных моделей readiness=503.
- Совместимый jury API, расширение UI для правил и неопределённых кандидатов,
  серверные ссылки на frontend. Unknown не превращается в чистое видео.
- Оценка известных меток по классам, 2×2 матрицы, macro доступных классов,
  временное сопоставление с допуском 5 секунд, пропуски бинарного gate, отказы,
  время/устройство и отдельные отчёт/ZIP без кадров.
- Исследовательские секции в 02/03; запуск обучения и оценки действий только явно.

## Что требуется для реального эксперимента

1. Совместно с автором каталога подтвердить сопоставление видимых действий с типами,
   включая условия, которые нельзя установить по кадрам. Не заменять это юридическим
   выводом из бинарной метки.
2. В режиме `per_type_v1` проверить присутствие/отсутствие заявляемых типов у
   конкретных train/validation окон. Записать решения в `action_review` **того же
   events.csv**. Остальные типы оставить неизвестными. Для оценки фоновых тревог
   отдельно проверить отсутствие типа во всём соответствующем видео.
3. Для заявляемых типов добавить независимые train/validation примеры при их отсутствии;
   текущий split не переставлять ради метрик. С 1–2 видео на тип достоверность низкая.
4. Провести отдельный воспроизводимый запуск, проверить ошибки/отказы/локализацию,
   включить только оценённые типы. Реальный полный проход backend/frontend с checkpoint
   остаётся невыполненным.

Не утверждаются precision/recall/F1 реального action-распознавания, временная точность,
приемлемая скорость или надёжное обнаружение неизвестных типов. Общий кабинет,
люди и неизвестные сеансы ограничивают переносимость; полная временная разметка
положительных видео отсутствует. Жёсткое завершение зависшего decoder/GPU-вызова
потребует process isolation; текущая отмена кооперативная.
