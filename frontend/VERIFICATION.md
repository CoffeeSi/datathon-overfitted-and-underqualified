# Проверка интеграции Фокуса

Дата: **18 октября 2026**, Asia/Qyzylorda. Локальный Windows-хост, Next.js dev server
и затем production-сборка на `127.0.0.1:3000`, FastAPI на `127.0.0.1:8000`. Использованы только синтетические
JPEG и 8-секундный MOV; реальные банковские кадры и разметка не участвовали.

## Реальные HTTP-запросы

- С unconfigured backend: BFF service вернул `200`, `health=online`, `ready=false`;
  отправка синтетического MOV вернула `503 provider_unavailable`.
- С явно включённым mock: service вернул `ready=true`, `provider=mock`.
- MOV размером 4 425 440 байт прошёл через BFF: `202`, затем `processing → done`.
  Получены два синтетических Finding и provider `mock`.
- Валидный MOV, дополненный контейнерным `free` atom до **100 MiB (104 857 600 байт)**,
  принят через BFF: `202 → done`.
- MOV размером **100 MiB + 1 байт** получил `413 upload_too_large`.
- Chunked multipart более 102 MiB **без Content-Length** получил `413 upload_too_large`.
  Это проверяет ограничение потока, а не только предварительную проверку заголовка.
- Чужой Origin: BFF `403`; неверный multipart: BFF `422`.
- Расширение `.mp4`: BFF `415`; повреждённый `.mov`: BFF `422`.
- Неизвестное задание: BFF `404 job_not_found`.
- Неверный ключ: защищённый **FastAPI endpoint напрямую** вернул `401`.
  Эта проверка не подменяет ключ работающего Next.js и не является проверкой `401` через BFF.
- Во всех проверенных BFF-ответах установлен `Cache-Control: private, no-store, max-age=0`.

Файлы создавались блоками по 1 MiB, HTTP-клиент использовал file-backed Blob либо
поток. BFF передаёт тело потоком с backpressure, не вызывая `formData()`/`arrayBuffer()`
для полного видео. Пиковая память сервера под нагрузкой отдельно не профилировалась;
эти проверки не являются нагрузочным тестом или оценкой скорости ML-модели.

При отсечении заведомо слишком большого chunked-запроса существующий Starlette parser
зафиксировал `ClientDisconnect` в локальном логе. Клиент получил корректный безопасный
`413`, задание не создано. Backend-код и публичные контракты не менялись.

В интеграционной проверке найден и исправлен случай Next.js Node adapter:
`Request.url` может содержать `localhost`, когда браузер использует `127.0.0.1`.
Проверка Origin теперь учитывает реальный Host и не доверяет присланному
`X-Forwarded-Host`. Добавлен регрессионный тест для разрешённого и чужого origin.

## Воспроизводимость и границы

- `npm run lint`, `npm run typecheck`, `npm run build` — успешно.
- `npm test` — **70 тестов в 7 файлах прошли**. Кроме API проверены polling,
  отмена и устаревшие ответы, upload, связь timeline/списка/видео, ошибки кадров,
  клавиатура, происхождение локального файла и точность таймкодов.
- Playwright на production-сборке, установленный Chrome: **6 тестов прошли**.
  Выполнены desktop/mobile, keyboard-only навигация и восстановление фокуса,
  processing → done, три verdict/failed, восстановление выбранного события по URL,
  поиск, evidence gallery, JSON export, 404 и настоящий upload → mock result.
  Проверены перемотка локального MOV к событию и повторное открытие после reload.
  После финальной настройки высоты плеера отдельно повторены desktop, mobile/keyboard
  и accessibility: **3 проверки прошли**, весь evidence-кадр помещается в область просмотра.
- Axe: на главной и экранах violation/no_violation/failed не обнаружено нарушений
  проверенных правил WCAG 2 A/AA и 2.1 AA. Это автоматическая проверка,
  не полноценный аудит всеми вспомогательными технологиями.
- Визуально просмотрены screenshots desktop 1440px и mobile 390px.
  На ширинах 320, 390, 768 и 1366px у главной и review нет горизонтального
  переполнения всей страницы; списки событий и timeline прокручиваются внутри.
- `git diff --check` — успешно. В клиентских static bundles не найден локальный
  тестовый API key. Backend, ML, notebooks, events.csv и split не изменены;
  SHA-256 обоих CSV совпали с исходными.

API unit tests: `npm test -- tests/api-contracts.test.ts tests/api-policy.test.ts` —
**30 тестов прошли** после исправления Origin. Они проверяют wire-контракты,
конечные таймкоды, согласованность verdict/findings, неизвестные типы и коды ошибок,
границу origin, пути заданий и ограничение потока без Content-Length.

Полный набор команд, явный demo mode и дополнительные browser tests описаны
в [README.md](README.md). Синтетический успешный ответ подтверждает интеграцию
frontend с контрактом API; типизированный реальный ML provider ещё не подключён.

Подробный локальный протокол находится в игнорируемом `runs/frontend-smoke/`.
В этот документ не включены идентификаторы заданий, кадры, API key или полные ответы.
