# Контролируемое обучение на аугментациях

Прежние 20 эпох были несопоставимы: 87 исходных окон давали 120 обновлений,
а 435 окон с вариантами — 560. Доля оригиналов упала до 20%. Это смешивало
влияние данных и количества обновлений optimizer.

Новый `ml/matched_augmentation.py` фиксирует два варианта до оценки:

- control: только оригиналы;
- mild_augmented: вероятность оригинала 80%, каждого преобразования — 5%.

Одинаковы pretrained R3D-18, начальная бинарная голова, preprocessing/ROI,
seed 42, batch 16, lr 0.0003, AdamW и **ровно 120 обновлений**. Выбор с
возвращением балансируется по классам и каноническим видео; разные отметки
X-4/X-47 сохраняются. Все источники остаются в прежнем split 30/10.

Признаки извлекаются только из train. Обучается бинарная голова; backbone
и BatchNorm проверяются хешем до/после. Validation не выбирает эпоху или
checkpoint: оба `last.pt` сохраняются до первого предсказания validation.
Формат совместим с существующим загрузчиком бинарной модели. Поле epoch=1
обозначает одну фиксированную фазу, а реальный бюджет — matched_steps=120.

После обучения отдельно оцениваются 10 исходных validation-видео и 40 их
производных с фиксированным порогом 0.5. Это классификация окон вокруг
известных отметок, а не оценка автоматической временной локализации.
Четыре варианта каждого источника не являются независимыми видео. Эта
development validation уже использовалась для диагностики; независимого test нет.

Из корня установите `PYTHONPATH=src` (PowerShell: `$env:PYTHONPATH='src'`):

```sh
python -m overfitted_underqualified.ml.matched_augmentation --config configs/r3d18_matched_augmentation.yaml
```

Каждый запуск создаёт свежие `runs/r3d18_matched_*` и `reports/evaluation_matched_*`.
План и сводка сохраняют конфигурации, SHA, историю шагов, результаты по каждому
преобразованию и ограничения. Настройки сервиса не заменяются автоматически.
100% на новых источниках не гарантируются.

Текущая геометрия уменьшает мелкие купюры примерно до нескольких пикселей.
Бинарный ответ не подтверждает распознавание купюр, владельца денег, конкретного
действия или юридического нарушения. Для этих задач нужны отдельные наблюдаемые
признаки и проверенные положительные/отрицательные примеры.
