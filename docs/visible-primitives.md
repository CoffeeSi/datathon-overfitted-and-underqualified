# Видимые признаки и история обслуживания

Продолжение: [отдельный детектор банкнот и аудит дополнительных данных](banknote-sequence.md).
Исторические R3D-эксперименты ниже сохранены; новые объектные рамки не меняют их метрики.

Это исследовательская проверка цепочки «кассир получил банкноты → клиент ушёл от
стойки → банкноты остаются на столе». Она использует текущие видео и неизменный
`within_room_unique_video` split: 30 train / 10 validation. Состояние «клиент ушёл»
получается из последовательности наблюдений, а не из бинарной метки нарушения.

## Разметка и её границы

Единственный редактируемый источник — `data/annotations/events.csv`. Новый столбец
`primitive_review` содержит JSON с хешем видео, методом просмотра, временем проверки
и списком точечных наблюдений. Исходные девять полей и `action_review` сохранены.
Новые точки описывают видимые признаки; они не заменяют таймстамп нарушения и не
вводят интервальную разметку нарушений. X-4/X-47 остаются одним видео с двумя
исходными событиями; признаки не дублируются по алиасам.

Три независимых бинарных выхода:

- `client_at_counter`: клиент находится у обслуживаемой стойки в конечном кадре.
  Человек за стеклом, у входной двери или сотрудник за своим рабочим местом не
  считается клиентом у стойки.
- `banknotes_on_counter`: в конечном кадре на поверхности стола лежат банкноты.
  Документ, банкноты только в руках или в счётной машинке не подходят. Перекрытая
  поверхность не даёт оснований записывать отсутствие банкнот.
- `cash_handover_to_cashier`: в предыдущие две секунды видна передача банкнот
  клиентом кассиру, напрямую или через стол. Передача документа и возврат денег
  клиенту не подходят. Для этой метки нужен просмотр последовательности.

Метка `0` — явно проверенное отсутствие конкретного признака. Отсутствующий ключ
— unknown, он маскируется в loss и метриках. Бинарное «Без нарушения» не создаёт
отрицательные primitive-метки. Просмотр отдельных кадров не подтверждает полноту
разметки всего видео; записи не объявляются независимой человеческой экспертизой.

`experiments/review_primitives.py` создаёт приватные крупные контактные листы с
точными временами. Кадры остаются в игнорируемом `data/local_artifacts/`.

## Реализация

- `ml/primitive_data.py`: определения признаков, проверка sparse-разметки,
  причинные окна и Dataset с масками. Берутся 16 кадров **до точки включительно**;
  у начала видео будущие кадры не используются.
- `ml/primitive_model.py`: frozen R3D-18 и три sigmoid-выхода. Используются
  существующие masked BCE, вычисление метрик и кэш frozen-признаков.
  Балансировка вычисляется только по train. Backbone и BatchNorm проверяются
  на неизменность, восстанавливаемый checkpoint не скачивает pretrained-веса.
  `configs/primitives.yaml` использует один общий вид; `primitives_multiview.yaml`
  объединяет признаки общего вида и увеличенной области стола. Backbone общий,
  обе области имеют одинаковую Kinetics-нормализацию; порядок областей сохранён в config.
- `ml/cash_sequence.py`: память о приёме наличных, уходе клиента и устойчивом
  наличии банкнот; пропуски наблюдений, неоднозначные состояния и истёкшая
  предыстория приводят к отказу. Есть повторные события после завершения эпизода.
- `ml/primitive_inference.py`: полный проход с начала видео, без бинарного gate
  и без доступа к CSV. Каждый вызов создаёт новое состояние цепочки. В результате
  остаются вероятности всех признаков, основания и времена кандидатов.
- `ml/primitive_evaluation.py`: проверка соответствия checkpoint/config/данных,
  метрики по известным точкам, FP/FN, полный проход по всем validation-видео,
  временное сопоставление и ZIP с числовыми результатами.

## Запуск

Команды выполняются из корня с `PYTHONPATH=src`. PowerShell: `$env:PYTHONPATH='src'`;
Linux/Brev: `export PYTHONPATH=src`. Используйте Python окружения проекта.

```sh
python -m overfitted_underqualified.ml.primitive_model --config configs/primitives.yaml
python -m overfitted_underqualified.ml.primitive_model --config configs/primitives.yaml --train
python -m overfitted_underqualified.ml.primitive_evaluation --config configs/primitives.yaml --checkpoint runs/RUN/last.pt --output reports/evaluation_primitives_NEW --device cuda
python -m overfitted_underqualified.ml.primitive_inference --checkpoint runs/RUN/last.pt --video path/to/new_video.mp4 --output data/local_artifacts/new_video_primitives.json --device cuda
```

Перед новым обучением задайте новый `output_dir`; существующие артефакты не
перезаписываются. Для исторического checkpoint используйте его сохранённый config
и соответствующий снимок `events.csv`. При переносе на Brev можно изменить пути и
устройство, но не хеши, preprocessing или параметры оценки.

В 02/03 есть исследовательские секции: конфигурация, покрытие, запуск по явному
флагу, learning curves, сравнение выходов, ошибки и временные траектории. Обычный
Run All не начинает новое обучение или полный primitive-scan.

## Что означают результаты

Кандидат `unsecured_accepted_cash` имеет статус `research_candidate` и требует
проверки. Ссылка из существующего каталога — возможное нормативное основание,
применимость которого не доказана этой цепочкой. Три признака не устанавливают
тождество купюр, собственника, завершение операции, возврат клиенту или проводку.
Основной FastAPI analyzer не переключается на эксперимент; API-контракты сохранены.

Отсутствие кандидата возвращает `insufficient_data`, а не юридическое «нарушений нет».
Неизвестные участки и неполная предыстория не становятся отрицательными примерами.
Полная precision/F1 по типу остаётся неопределённой без полной временной разметки
и проверенных фоновых видео. Window-метрики считаются отдельно; множество точек
одного видео не равно множеству независимых примеров. Validation уже многократно
просматривалась, кабинет/люди общие, независимого test здесь нет.

Последние измерения и сохранённые веса перечислены в
[отчёте исследования](../reports/primitive_study_20261018.md). У второго варианта
полная траектория X-38 показывает receipt около 7–9s и уход клиента около 27s,
но ошибочное «банкнот нет» сбрасывает историю. Это локализует проблему в визуальном
выходе банкнот; повторное изменение временного порога её не устраняет.
