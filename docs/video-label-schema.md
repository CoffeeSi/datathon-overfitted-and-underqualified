# Video annotation schema

The optional `primitive_review` metadata now includes reviewed normalized xyxy
`banknote_boxes` on explicit complete endpoint frames, plus `sequence_grid_review`
for a scoped full-duration sampled visual sequence. These retain the original event
labels/timestamps; they do not establish continuous legal ground truth. See
[definitions, provenance and limitations](banknote-sequence.md).

This is the current contract for `data/annotations/events.csv`, consumed by
`notebooks/01_eda.ipynb`. The CSV is the annotation source; this document describes
its fields. [video-labels-split.md](video-labels-split.md) is a readable snapshot,
not a second source of training labels.

## Provenance and intended use

The dataset has two different kinds of annotation. Keep them separate:

- Source supervision: the supplied binary labels and event time markers. IDs are
  normalized for matching files; English labels and numeric seconds are mechanical
  conversions of the source values.
- Provisional interpretation: descriptions, tags, categories and rule references were prepared from
  the supplied text descriptions. They were not independently verified by a human
  watching the videos, and were not generated by a model detecting actions in the
  footage. Some wording and rule references were changed during interpretation.

The EDA notebook checks files and annotation consistency. It does not confirm the
truth of provisional descriptions or the applicability of rule references. For the binary
baseline, use video as input and `source_label` as the target; use `timecode` to
locate the annotated event. Do not feed descriptions, event markers, legal text or
other annotations to the classifier as video-derived features. Descriptions, event tags, categories and rule references are
exploratory notes, not verified targets for multiclass event training.

## Current CSV fields

The following fields follow the CSV column order. Empty values are missing or not
assigned, not evidence that a reviewer ruled out an event.

- `clip_id`: unique normalized video ID such as `X-1`. Latin `X` and Cyrillic `Х`
  in filenames map to Latin `X`; numeric leading zeros are removed. Original
  filenames and relative paths are kept in the inventory and enriched output.
- `timecode`: supplied event marker, currently `MM:SS`; empty for negative rows.
  It is not a verified event start/end. EDA also accepts nonnegative seconds or
  `HH:MM:SS`, with subordinate minute/second components below 60. A violation
  requires a valid marker inside the corresponding video.
- `source_label_ru`: supplied Russian label, `Нарушение` or `Без нарушения`.
- `observed_event`: Russian description of the action or state. On 2026-10-18,
  missing-text placeholders on 20 negative source rows were replaced after visual
  review of 1 Hz frame sequences across 19 unique videos, plus selected original
  frames. This sampled review does not certify every short action or legal condition.
  See [review provenance](../reports/visible_descriptions_20261018.md).
- `observed_event_type`: provisional event tag. The current negative rows
  retain the supplied `not_reported` tag even where visible prose was added.
  It means the original type was not assigned, not that the video is empty.
  These tags are not a verified event taxonomy and were not inferred from the new prose.
- `candidate_violation_type`: possible compliance category,
  empty for current negative rows. Category counts in EDA summarize these
  hypotheses, not independently annotated violation types.
- `legal_basis`: optional candidate reference to National Bank Regulation №231 only.
  Empty means no confirmed reference in the supplied 231-only revision; it does not
  change the binary label. Applicability conditions remain in the rule catalog.
  retained or modified during interpretation. EDA preserves this text without checking correctness,
  currency or applicability. Empty for current negative rows.
- `source_label`: machine-readable equivalent of the Russian source label:
  `violation` for `Нарушение`, `no_violation` for `Без нарушения`. Both must agree.
- `timecode_sec`: numeric seconds converted from `timecode`, empty when absent.
  EDA recomputes this field in memory and in `events_enriched.csv`; edit the source
  `timecode`, not the numeric conversion.

## Removed fields and naming changes

`confidence` and `review_status` have been removed. They were provisional estimates,
not human-review results or model probabilities. There is no automatic confidence
calculation or manual-review completion flag in the current event CSV.

The previously removed manual observation/confidence columns remain absent.
No human review should be inferred from any current event field.

## Annotation rules

1. Preserve source labels and markers independently of provisional notes. Disagreement
   with a rule interpretation does not automatically change the supplied label.
2. `no_violation` means the supplied annotation reported no violation. It does
   not mean nothing happened or every possible category was independently checked.
3. Preserve uncertainty in descriptions. A check not visible on camera does not
   establish that it never occurred. Authorization, transaction status and similar
   external facts cannot be assumed from a single frame.
4. A timestamp marks an event, not its duration. Do not automatically label every
   adjacent frame positive. A context window around a timestamp is a sampling choice, not a labeled event duration.
5. The team accepts the supplied labels and markers for the baseline. This does not
   turn provisional descriptive notes into independently verified multiclass targets.
6. Edit the CSV, regenerate its Markdown snapshot, then rerun EDA. The notebook
   never rebuilds annotations from Markdown and never overwrites the source CSV.

## Related files

- `data/processed/video_inventory.csv`: filenames, IDs, SHA-256 hashes, metadata
  and decoding checks measured by code from the video files.
- `data/processed/events_enriched.csv`: eligible source records, provisional notes and
  measured metadata joined for analysis, retaining every source event and adding
  `canonical_clip_id`. It is generated, not the editable source.
- `data/processed/duplicate_map.csv`: SHA-256-based source-to-canonical ID mapping.
  Handled copies appear in `dataset_notes.csv`; conflicting labels remain errors.
- `data/processed/training_videos.csv`: one row per unique video, with all original
  IDs in `source_clip_ids` and distinct markers in `event_times_sec` as JSON arrays.
  Exact copies do not become multiple video-level training examples; different
  event markers are preserved rather than dropped.
- `data/processed/validation_issues.csv`: file/ID/label/timestamp errors and warnings.
- `data/processed/split_proposal.csv`: proposed grouped train/validation assignment
  for canonical IDs in `training_videos.csv`.
  The agreed `within_room_unique_video` protocol uses source binary labels and file hashes; scene similarity is diagnostic only. Exact copies remain together. Descriptive notes and legal interpretations are not split features.

Only `events.csv` supplies event labels and timestamps. It has been accepted by the
team for the current baseline; no separate approval table or action catalog is required.
This agreement does not establish independent legal verification of the descriptive notes.

`events.csv` is explicitly allowed by `.gitignore`. There is no separate scene annotation file. The documentation snapshot is not an independent annotation source.
The word "split" in that snapshot concerns event/category columns, not train/validation.

## Point annotation and readiness

Each positive source record has one event marker in `timecode`; `timecode_sec` is
its numeric conversion. Negative rows have no violation marker. No start/end bounds
or per-event review flags are required. EDA checks source IDs, labels, timestamps,
matching video files, decoding, and duplicate consistency. It does not reapprove events.

All event markers survive deduplication in `training_videos.csv` (`event_times_sec`).
X-4 and X-47 share one canonical video but retain different source event markers.
A context window is a sampling parameter, not annotation of event duration.

The team agreed to a preliminary within-room split by unique video SHA-256,
approximately 75/25 with seed 42 and both binary classes in each subset. All aliases
and event markers for a canonical video inherit its subset. `split_proposal.csv`
is generated and tracked to retain the assignment; `events.csv` remains the sole
editable label source. Split changes invalidate direct comparisons to earlier runs.

This protocol does not establish camera/session independence. Related recordings,
people and background may cross subsets; validation is small and not a final test set.
P0 baseline readiness and independent evaluation readiness are reported separately.
See [temporal-annotation-workflow.md](temporal-annotation-workflow.md).

## Action-window supervision

Optional `action_review` JSON cells in the same `events.csv` hold typed targets,
explicit window absences and unknowns. They do not change binary labels or timestamps.
On 18 October 2026 the owner confirmed the batch in chat. This is recorded as an
owner attestation, not a new independent frame-by-frame review. Unmapped or explicitly
unknown cases remain masked. Confirmed absences cover the sampled four-second window
only; `whole_video_absent_types` remains empty. Historical binary input hashes and
registered metadata-only revisions are preserved.

## Visible primitive supervision

Optional `primitive_review` JSON in the same CSV contains independent, sparse
visual observations, not additional violation timestamps. Schema
`visible_primitives_v1` pins the video hash and two-second causal context. Each
point has `time_sec`, explicit 0/1 `labels`, inspected `evidence_seconds`, and a note.
Missing keys stay unknown. The first two targets describe the endpoint; cash
handover describes the trailing window. See [definitions and workflow](visible-primitives.md).

The initial review covers 93 selected points in 14 canonical videos (54 train /
39 validation). Original source fields and action targets are unchanged, including
X-4/X-47's distinct violation points. This is a sampled visual review, not a claim
of complete human-reviewed action absence across a video. The versioned binary
metadata revision explicitly permits this new column while protecting labels,
timestamps, source ID order and every other unchanged field. Historical action
experiments retain their exact source snapshots.
