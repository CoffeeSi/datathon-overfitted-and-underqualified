# Дополнительные видео: импорт, обучение и проверка

Выполненный [эксперимент 18.10](../reports/binary_augmentation_study_20261018.md)
сохраняет реальные результаты обеих моделей: в этом запуске аугментации не
улучшили F1. Прежние рабочие веса не заменены.

Дальнейшее [сравнение с одинаковым числом обновлений](matched-augmentation.md)
проверяет 80% оригиналов / 20% аугментаций и фиксированный последний checkpoint.

Локальные источники скопированы в игнорируемый `data/raw/supplemental/`:

- `augmentations/` — 168 файлов `X-N__variant.mov`;
- `synthetic/` — восемь S-сценариев и один файл без соответствующей разметки;
- `source_metadata/` — неизменённые копии предоставленных CSV и XLSX;
- `audit.json` — сгенерированное происхождение, SHA, тайминг и назначение исходников.

Правильный каталог проекта — `data/raw/`. Исходные файлы на Desktop сохранены.
`events.csv` остаётся единственным редактируемым источником меток X-роликов.
Внешний CSV проверяет соответствие меток и времени, а не переопределяет их.

## Защита split

Каждый вариант наследует канонический ID и исходный split. X-47 объединяется
с X-4, X-48 — с X-5, но разные отметки событий в этих видео сохраняются.
128 train-записей дают 120 канонических вариантов (30 × 4), ещё 40 относятся
к десяти validation-источникам. Исходный split 30/10 не меняется.

Для нового бинарного R3D-18 используются исходные train-окна и все четыре их
варианта: warm, cool, CCTV и mirror. Вес каждой канонической группы сохраняется;
количество аугментаций не увеличивает её вклад относительно остальных видео.
Mirror разворачивается обратно перед фиксированным ROI, поэтому пространственная
область совпадает с оригиналом. Это не обучение нового распознавателя всех
юридических типов; объектный детектор купюр и его прежние результаты сохранены.

При обучении validation состоит из прежних десяти оригиналов. Только после
обучения 40 validation-аугментаций проходят отдельную проверку устойчивости
с порогом 0.5. Оригиналы и каждый вид преобразования оцениваются отдельно.
Сорок вариантов — коррелированные проверки десяти источников, не 40 новых
независимых тестовых видео. Их результаты не выбирают checkpoint или порог.

Синтетические S01–S04 не имеют канонического X-ID в `events.csv`. Имена и
описания из XLSX не становятся метками X-роликов. Они сохранены для отдельной
подготовки разметки; файл без метаданных исключён из обучения и оценки.

## Повторение

Из корня с `PYTHONPATH=src`:

```sh
python experiments/import_supplemental_videos.py --augmented-dir PATH/videos_augmented --synthetic-dir PATH/videos --labels PATH/labels_augmented.csv --workbook PATH/annotations.xlsx
python -m overfitted_underqualified.ml.train --config configs/r3d18_augmented.yaml --output-dir runs/NEW_AUGMENTED_RUN
python -m overfitted_underqualified.ml.augmented_evaluation --checkpoint runs/NEW_AUGMENTED_RUN/best.pt --output-dir reports/evaluation_augmented_NEW --device cuda
```

При переносе проекта повторите импорт на новом компьютере и обновите SHA
локального `audit.json` в конфигурации. Checkpoint хранит точные хеши и
происхождение своего запуска; старые манифесты и результаты не переписываются.
Восстановление модели для обычного инференса не требует внешнего аудита.

В 02 основной запуск выбирается через `TRAIN_CONFIG=configs/r3d18_augmented.yaml`;
`RUN_TRAINING` остаётся явным переключателем. 01 показывает распределение новых
источников, 02 — настройки/сохранённый эксперимент, 03 — сравнительную проверку
оригиналов и вариантов. Реализация находится в `ml/augmented_data.py`,
`ml/train.py` и `ml/augmented_evaluation.py`.
