## Разметка и обучение

`events.csv` остаётся единственным редактируемым источником меток и точек времени.
Бинарные метки, время и split сохранены. В CSV применена явная замена только
`legal_basis` на предоставленную версию №231; [запись миграции](../data/annotation_revisions.json)
связывает старый и новый SHA-256. Старые эксперименты не изменены. `configs/actions.yaml`
содержит конфигурацию эксперимента и свидетельство проверки, привязанное к SHA-256
CSV; это не второй набор меток. По умолчанию `review.label_mode: per_type_v1`:
только явные решения `action_review` внутри CSV становятся целями обучения.
Существующие `observed_event_type` остаются кандидатами. Подтверждение наблюдения
не подтверждает автоматически все условия категории каталога. Пропущенный тип
неизвестен. Само `no_violation` не даёт отрицательной action-метки.
Глобальные `catalog_mapping_verified` и `complete_action_lists` относятся к прежнему
режиму `listed_actions`. Для частичной проверки не нужно включать их: каждое
известное значение имеет собственное обоснование. Восстановление проверяет решения
из manifest, их окно/видео/каталог и положительные/отрицательные train-примеры.

`action_data.py` повторно использует проверку SHA-256 видео, покрытия исходных ID
и отсутствия дубликатов между выборками. Разные отметки X-4/X-47 сохраняются.
Сопоставление кандидатов использует существующий каталог. X-15, X-26, X-38 и X-44
исключены из автоматических целей: не установлены содержимое сумки, продолжающееся
обслуживание или факт приёма наличных. Явная проверка может разрешить неопределённость.
Неподдерживаемые/неоднозначные
теги перечислены в аудите и не превращаются в фон.

Выбран отдельный frozen R3D-18 с sigmoid-головой: действия могут сосуществовать.
16 кадров и pretrained preprocessing совпадают с бинарным baseline, декодирование
переиспользуется. Известные действия внутри одного окна объединяются в набор;
разные отметки канонического видео не теряются. Masked BCE игнорирует неизвестные
цели. Перед обучением каждый класс обязан иметь train-положительные и известные
отрицательные примеры. Сейчас нет заполненных per-type решений: обучение остановлено
до создания модели и загрузки pretrained-весов.
Положительное обучение без отрицательных примеров привело бы к постоянным тревогам.

`action_train.py` сохраняет отдельный `last.pt`, mapping, версию схемы, конфигурацию,
происхождение pretrained-весов, seed, хеши CSV/split/catalog/видео, историю, environment
и прогнозы validation. Используется последняя заданная эпоха, не подбор на validation.
Backbone и BatchNorm заморожены; validation не обновляет веса. Старые runs не используются
для записи. При восстановлении `weights=None`, скачивания pretrained-весов нет.

Из корня с `PYTHONPATH=src`:

```sh
python -m overfitted_underqualified.ml.action_train --config configs/actions.yaml
# Только после подтверждения разметки; выбирайте новый output_dir:
python -m overfitted_underqualified.ml.action_train --config configs/actions.yaml --train
```

PowerShell: `$env:PYTHONPATH='src'`; Linux/Brev: `export PYTHONPATH=src`.
Нужны зависимости основного проекта, `requirements-ml.txt` и для HTTP также
`requirements-backend.txt`. Новых ML-библиотек не добавлено.

Последний вариант требует просмотра всего оригинала. Проверяйте перечисленные

Ответы живут в памяти страницы до скачивания, JSON можно загрузить обратно.

```sh
python -m overfitted_underqualified.ml.action_review --config configs/actions.yaml --decisions data/local_artifacts/action_review_decisions.json
# После проверки показанных ID применить решения к единственному CSV:
python -m overfitted_underqualified.ml.action_review --config configs/actions.yaml --decisions data/local_artifacts/action_review_decisions.json --apply
```

Без `--apply` выполняется проверка. Импорт проверяет исходные SHA-256, типы,
временной контекст, дубликаты и противоречия между отметками канонического видео.
Меняется только optional-колонка `action_review`; бинарные метки, время, описания
и split сохраняются. Транспортный JSON обучением не читается и не является
вторым источником разметки. До применения сохраняется историческая копия CSV
в игнорируемом `data/local_artifacts/annotation_snapshots/<SHA>/events.csv`.
Существующее решение строки не заменяется без `--replace-existing`: для повторной
проверки нужно явно собрать весь сохраняемый набор решений этой строки.

В `action_review` хранится JSON `action_window_review_v1`: `present_types`,
`absent_types`, `whole_video_absent_types` (подмножество отсутствующих), `center_sec`,
`window_sec`, `reviewer`, `reviewed_at` с часовым поясом, `evidence_note`,
`video_sha256` и `catalog_sha256`. Пропущенный тип остаётся неизвестным.
Центр положительной строки берётся из её единственного исходного таймстампа;
для строки без таймстампа — из середины видео. Новая временная разметка не создаётся.
Отсутствие относится ко всему входному окну из `sample_times()` с учётом границ видео.

После импорта укажите напечатанный `events_sha256` в **action-конфигурации** и
используйте новый каталог запуска. Старые бинарные checkpoints привязаны к полному
хешу прежнего CSV: для воспроизведения оценки передайте `historical_events_path`
как `events_path`. Строгие проверки provenance сохраняются. Исключение для текущей
юридической правки и добавления описаний задаёт только точная пара хешей
в `data/annotation_revisions.json`:
binary evaluation проверяет сохранность всех полей кроме `legal_basis` и пишет оба
хеша в новый отчёт. Для отдельно зарегистрированного `binary_metadata_revision_v1`
разрешена только замена `observed_event` (и `legal_basis`, если он отличается от
исторической версии). Это не разрешает изменения меток, времени, тегов или action_review.
Решения action-проверки в настоящий CSV пока не импортировались.

## Неизвестное видео и каталог

`action_inference.py` не читает CSV/split и не выбирает тип по имени файла.
Бинарный scanner выдаёт окна; на каждом положительном окне отдельная модель
предсказывает вероятности действий **до** объединения. Группируются только
последовательные окна одного типа. Разные типы и разрывы с отказом не склеиваются.
Бинарный score хранится отдельно от type confidence. Бинарный gate экономит вычисления,
но его пропуски ограничивают recall всей цепочки; это явно измеряется в evaluation.

Фиксированные пороги: type ≥0.7 — поддерживаемое действие; все оценки ≤0.2 —
низкие оценки известных действий; промежуточные — отказ. Это эвристика,
не гарантия обнаружения неизвестного класса и не калиброванная вероятность.
Можно включить только обученные типы с положительными и отрицательными validation-примерами.
`enabled_types` задаётся явно после просмотра оценки. Наличие поддержки в каталоге
само по себе не разрешает включить тип. В поставленной конфигурации список пуст.

`link_action()` проверяет тип и добавляет реальные ссылки, условия применимости,
ограничения видимости; `legal_conclusion=null`. Предсказание является кандидатом
для проверки специалистом. Отдельный тип не доказывает, что юридические условия выполнены.
Положительный бинарный сигнал без принятого action-типа даёт `insufficient_data`,
даже при низких action scores. Если часть событий распознана, возвращаются findings
и отдельный список неопределённых окон. Без бинарных кандидатов — `no_violation`
в пределах возможностей текущего сканера, не доказательство отсутствия нарушений.

```sh
python -m overfitted_underqualified.ml.action_inference --binary-checkpoint runs/BINARY/best.pt --action-checkpoint runs/ACTION/last.pt --enabled-type client_identity_check_not_visible --video input.mov --output reports/evaluation_actions_manual.json
```

## Backend и UI

В `configs/action_service.yaml` задайте пути **обоих** checkpoints, device и проверенные
`enabled_types`, затем окружение:

```text
FORTEBANK_ANALYZER_FACTORY=overfitted_underqualified.backend.local_analyzer:create_analyzer
FORTEBANK_ACTION_CONFIG=configs/action_service.yaml
```

Обычный запуск сервиса остаётся прежним. Модели загружаются один раз в factory.
Нет файла, несовместимый mapping/catalog, неподдерживаемый тип или недоступное устройство —
`/readyz` отвечает 503; mock автоматически не подставляется. Сейчас реальный режим
отключён по умолчанию (`enabled_types: []`): реальные исследовательские веса есть,
но полезное качество типов не подтверждено. Актуальные измерения приведены в
[статусе распознавания](../reports/action_recognition_status.md).

Инференс работает в потоке под одним lock. Отмена выставляет кооперативный сигнал
и **дожидается завершения потока**, сохраняя lease heartbeat и занятый слот.
Проверки отмены есть между batch/окнами и при извлечении кадров. Заблокированный
нативный decoder/GPU-вызов нельзя принудительно прервать потоком: timeout может
завершиться позднее. Для жёсткого ограничения wall time нужен отдельный процесс;
текущая реализация не обещает пяти минут на любом входе/устройстве.

Jury API проецирует исходные `AnalysisResult/Finding`, без новых обязательных полей.
UI endpoint дополнительно получает `source_links`, applicability, ограничения,
два score, `recognition_scope` и `unresolved_candidates`. Frontend проверяет тип ссылки,
HTTPS URL, численные границы и согласованность verdict. Показывает серверные ссылки,
условия и неопределённые таймкоды. Нормативные ссылки на клиенте не выдумываются.

### Разбор X-18 / X-2 и геометрия

Сравнение одного типа описано в [отчёте](../reports/identity_geometry_20261018.md).
`configs/actions_identity_control.yaml` и `actions_identity_roi.yaml` фиксируют
одинаковые 30 эпох и порог 0.7; различается только preprocessing. Вариант ROI
использует `aspect_letterbox_v1` и `[0,0.1,1,0.65]` по train-кадрам. Геометрия
сохраняется в checkpoint и одинакова в Dataset, оценке и полном инференсе;
несовпадение при оценке отклоняется. Старые checkpoints сохраняют исходный transform.

`target_types` ограничивает голову явно указанными типами с train-положительными
примерами. `cache_frozen_features: true` вычисляет frozen-признаки один раз в рамках
запуска, сохраняя masks и разные loader train/validation. Это ускорение не добавляет
примеров и не обновляет backbone или BatchNorm. Оба новых варианта выучили train,
но пропустили X-2: улучшение геометрии пока не дало прироста validation F1.
В ноутбуках добавлено чтение сравнения, learning curves и временных ошибок.

```sh
python -m overfitted_underqualified.ml.action_train --config configs/actions_identity_roi.yaml --train
python -m overfitted_underqualified.ml.action_evaluation --config configs/actions_identity_roi.yaml --binary-checkpoint runs/BINARY/best.pt --action-checkpoint runs/IDENTITY/last.pt --enabled-type client_identity_check_not_visible
```

Для повторного обучения задайте новый output_dir; существующие runs не заменяются.
Дополнительных независимых positive-видео нет; исходные метки и split сохранены.

Аудит текущего CSV и проверка новых правовых ссылок описаны в
[отчёте подготовки](../reports/action_preparation_20261018.md), машинный результат —
`reports/action_preparation_current.json`. Конфигурация привязана к актуальному SHA.
После последующего подтверждения владельца `training_ready=true`; исторический

## Оценка и ноутбуки

`02_detection.ipynb`: прежний бинарный эксперимент плюс аудит action-данных, график
покрытия, отдельный opt-in обучения и learning curves. По умолчанию обучение выключено.
`03_evaluation.ipynb`: раздел C, `EVAL_PROTOCOL=actions`, `RUN_ACTION_EVAL=true`,
`ACTION_CHECKPOINT_PATH` и `ACTION_ENABLED_TYPES`. Реализация в `action_evaluation.py`.

Если после обучения изменены только служебные примечания разметки, для старых
весов укажите `ACTION_EVAL_CONFIG=runs/<run>/evaluation_config.json`: он использует
точный локальный снимок исходных данных эксперимента. `ACTION_CONFIG` продолжает
указывать на актуальную разметку для новых запусков. Дословная цитата владельца
из текущего CSV и настроек удалена; обучающие цели не менялись.

```sh
python -m overfitted_underqualified.ml.action_evaluation --config configs/actions.yaml --binary-checkpoint runs/BINARY/best.pt --action-checkpoint runs/ACTION/last.pt --enabled-type client_identity_check_not_visible
```

Отчёт и ZIP создаются в новом `reports/evaluation_actions_<UTC>_<id>/`. Есть
per-class precision/recall/F1, support, отдельные 2×2 матрицы, macro только оцениваемых
классов, неизвестные цели, временные пары/пропуски, отказы, покрытие распознавания,
binary-gate coverage, время и устройство. Метрики окон и полной цепочки разделены.
Неоценимые precision/F1 — null, а не ноль. Допуск временного сопоставления — 5 секунд
до запуска. Полные видео оцениваются по всем поддерживаемым типам, включая отсутствующие
в train: их известные события учитываются как пропуски.

Полнота списка действий **у точки** не означает полноту временной разметки всего
положительного ролика. Его лишние тревоги остаются неразрешёнными, а full-video
precision/F1 не вычисляются как достоверные. FP на подтверждённом фоновом видео
можно посчитать. Общий кабинет/люди и неизвестные сеансы сохраняют ограничение
предварительного within-room split. Предыдущие baseline-метрики не переписываются.

Экспорт не содержит кадров или checkpoint. Outputs, execution counts и attachments
в ноутбуках очищаются перед Git. Тестовые фикстуры отделены от качества модели:
исторические блокировки до подтверждения не описывают последующие реальные запуски.
Сравнения checkpoint и ошибки сохранены в отчётах.

## Исследование видимых признаков

Альтернативный путь описан в [visible-primitives.md](visible-primitives.md).
Он обучает отдельные визуальные выходы и проверяет причинную цепочку с начала видео,
без binary gate. Используются дополнительные точечные факты `primitive_review`
в существующем CSV, тот же split и те же видео. Это исследовательский scanner;
основной FastAPI analyzer и его контракты не переключены на него. Полученный тип
остаётся кандидатом с непроверенной применимостью правила.
